What “Real Feel” establishes today

The stored targets originate in a Forte-based tuning workbook and a later power-steering correction. Manufacturer facts establish architecture or model revisions for some cars. Class rules establish permission; they do not prove a fitted assistance system or its force.

No calibrated real-car handwheel torque or vibration dataset was recovered for this 40-entry review. The percentages are RookForce interpretations. Their software calculation is explicit; physical equivalence remains unverified.

Evidence varies by car. An architecture source, a public steering-angle interface and an unresolved physical reference are shown separately in the car browser. Confidence in a source is not confidence that a percentage is physically correct.

Projection, units and missing inputs

Selected % = Real base % × (18 Nm ÷ verified maximum Nm) × mode × personal scale ÷ active-profile gain

Mode factors are Soft 0.80, Medium 0.90, Hard 0.95 and Real 1.00. Personal scale is 50–100% in 5-point steps; gain and personal scale are fractions in this equation. The implementation retains precision, rounds once half-up and caps LMU Strength at 100%.

A capped target is marked limited. The separate Real reference uses Real mode and 100% personal scale with the same torque and gain. A current live LMU readback equal to an achievable reference is distinct from merely matching a personal target.

Maximum torque must be established for the current connected device and capability. High Torque mode, a product-family name or Overall Force alone cannot establish it. Gain comes from the latest verified settings of the uniquely active RaceHub profile. Editing that profile withholds its settings and dependent target until current verification completes; keeping the profile list available does not verify the edited gain. Missing, stale, ambiguous or changed evidence withholds the dependent current target and guarded write.

The formula normalizes an accepted tuning reference. It assumes a proportional gain relationship for this product calculation; it is not a measured transfer function for the wheel, LMU mix, clipping, filtering or real car. RookForce does not edit RaceHub profiles to achieve the target.

How a stronger target could earn acceptance

Start with one exact car, one control and one observed issue. Record the game build, variant, setup, tyres, track conditions, output device and relevant profile. Compare a retained baseline and candidate at matched vehicle states, then report Retain, Revert or Inconclusive.

LMU's native telemetry documentation lists Steering Shaft Torque and FFB Output at 100 Hz in its example configuration. Those are game channels, not measured real-car or delivered wheel torque. Units, actual sample timing, assistance treatment and signal-chain stage need verification before calibration claims. A 100 Hz recording cannot resolve the whole 30–100 Hz vibration band without aliasing.

Useful cueing can be evaluated without a real-car laboratory. Claiming physical equivalence requires calibrated real-car reference data and an appropriate measured hardware response. No such experiment ran for this page.

Known provenance differences

The recovered corrected workbook and later research table differ on Peugeot wingless and ORECA competition treatment, several Evo Additional FFB values, and two Sensitivity floors. Current stored targets are displayed faithfully; this website changes none of them.

Retained series/class buckets also have a different Strength normalization from the exact-car table. The current exact automatic plan selects the exact-car table. A series-bucket result must not be presented as that same Real base.

Current build-review and exact-research metadata describe different checkpoints. They do not establish present compatibility or fresh validation for every car. Manufacturer guides can change too: Asetek's live baseline now differs from the historical workbook starting point.
